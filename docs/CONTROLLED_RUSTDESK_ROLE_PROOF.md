# 双端角色与当前登录态证明设计

更新：2026-10-13。本文是阶段 4 的协议设计，尚未实现或通过客户端验收。当前版本继续拒绝共享出口 IP 的中继，不启用兼容回退。

## 当前事实与缺口

- 固定 server 基线为 `a7736be5e40f85bfc141120dce587e836e5d4b80`，协议子模块为 `69cea8dafee147848ae88702029f4bf7df7224c3`。
- `backend/internal/service/rustdesk_connection_service.go` 以有效控制端令牌解析控制端，并要求被控端至少存在绑定设备、未撤销且未过期的客户端令牌；退出或撤销后拒绝新连接。**数据库令牌仍不能证明被控端此刻持有凭据或由真实设备发起本次连接**。
- `RegisterPeer` 没有登录凭据。设备在线、心跳较新、数据库里存在未过期 token、曾经登录过，都不能替代当前登录态证明。
- 当前 `hbbr` 核销只带会话 UUID 和观察到的 IP。共享 IP 的一端不能可靠区分为控制端还是被控端；放开同 IP 会允许一端占用两个名额。
- 当前 fork 的 WebSocket 分支直接采用 `X-Real-IP` / `X-Forwarded-For`；其值没有可信代理认证。不得将这些头当角色或出口证明，WebSocket 端口保持回环绑定。2026-10-13 经授权测试管理端口已改为指定局域网地址绑定，不是公网开放或可信代理认证。
- WebSocket 的 hbbs 消息处理传入 `secured=false`，含 token 的请求被拒绝。WebSocket 升级成功不等于带登录态远控成功。
- 2026-10-13 22:07 左右只读观察到两台测试设备均为在线、最近心跳且各有一个有效客户端令牌。这可用于运维排障，但仍只是数据库状态组合；没有设备私钥挑战、登录会话租约或退出后的不可续租证据，因此不计为当前登录态证明。

## 最小可信闭环

需要客户端配合，不能承诺未经修改的官方 1.4.9 客户端已支持。不得复用官方协议的未知字段或把会话 UUID 当秘密角色凭据。

1. 每台设备生成独立签名凭据，在操作系统密钥存储中保留私钥。服务端保存待审批公钥指纹，并通过可信管理员确认与设备绑定；自报 ID、UUID、IP 或公钥本身不能完成可信注册。公钥轮换必须重新确认，不能悄悄替换。
2. 客户端在已验证服务端身份的加密通道中，用当前 API 登录令牌和设备签名完成登录态证明。服务端挑战为随机一次性 nonce，签名上下文绑定协议版本、设备、用户、会话、服务受众和有效期；仅检查数据库 token 不足以完成这一步。
3. API 在线确认令牌未撤销、用户有效及设备绑定匹配，再签发最长 30 秒的短期登录租约，绑定登录会话及设备证明公钥。被控端必须以新挑战续租；退出、禁用或撤销令牌后不再续租。新连接在租约有效时仍逐次在线校验，不缓存放行结果。
4. `hbbs` 为每次连接创建不可重用会话，并为两端分别签发控制端/被控端角色票据。票据绑定双方设备、各自证明公钥、登录会话、会话 UUID、明确角色、hbbr 受众、过期时间及独立票据 ID；两端不得共用一个 bearer 凭据。
5. `hbbr` 在可信加密通道上发出新挑战，客户端提交本端角色票据和绑定该通道、挑战及票据 ID 的设备签名。API 在线校验设备/用户/登录会话和授权，再在事务中核销**指定角色**。同 IP 不影响角色判定；重复、换角色、换设备、换会话、换受众或过期证明必须拒绝，失败不得占用另一端名额。
6. API 不可达、缺少证明或协议版本不支持时拒绝新连接。不能回退到 IP、UUID 或“存在旧 token”的判断。两个角色验证完成后才能转发远控数据。

租约、挑战和票据均不得放入 URL、普通访问日志或明文 WebSocket；审计仅记录脱敏关联 ID、角色、设备和拒绝原因。

## NAT 与可信代理

- IP 仅用于风险审计和限流，不再作为双端身份。换出口后必须重新建立加密通道并完成挑战，不得把旧通道证明移用到新通道。
- 在上述闭环落地前，当前双 IP 授权在出口变化后失败属于安全优先行为；须新建授权，不改写已签发授权的 IP，也不能借此宣称跨 NAT 已兼容。
- 后续支持 WSS 时，终止 TLS 的代理必须具备独立认证、明确允许来源并覆盖转发头。只检查连接来源 IP 在允许列表中仍需考虑代理被同网段其他容器冒用的风险。
- 未部署可信代理认证前忽略转发头，或者拒绝代理路径；绝不从客户端自带头中获取准入身份。正常 WSS 必须有独立正向测试，不能把明文 token 拒绝测试记为 WSS 正常兼容。

## 实现影响范围

- 客户端：登录/退出、挑战签名、设备凭据存储、角色票据收取与中继证明。
- API：设备证明公钥审批、短期租约、票据及角色状态、撤销、原子核销、审计和数据库迁移。
- hbbs/hbbr：能力协商、可信加密传输、双端挑战和逐角色在线核销；TCP 与 WebSocket 必须使用同一准入语义。
- 部署：可信代理隔离、服务身份与票据签名密钥轮换；不复用内部 API 密钥作为客户端签名私钥。

因此这不是仅改一个 IP 判断即可安全完成的服务端补丁。当前工作区没有 RustDesk 客户端 fork；在选择修改版客户端或额外可信客户端组件，并明确凭据注册与丢失恢复方式前，服务端不预埋可被误用的降级接口。

## 必须新增的验收

| 场景 | 判定 |
| --- | --- |
| 同一出口的两台独立设备、不同出口双端 | 双端各自证明有效才允许 |
| 同一端连续冒充两角色、复制票据或会话 UUID | 拒绝，另一角色名额不变 |
| 被控端退出、租约到期、令牌撤销或账号禁用 | 新连接拒绝；恢复后重新完成证明 |
| API 故障，已有租约或票据仍未过期 | 新连接拒绝 |
| 出口变化、旧票据跨连接重放、并发核销 | 新挑战有效且角色最多核销一次 |
| 伪造转发头、绕过可信代理直连 | 不改变认证身份或被拒绝 |
| WSS 双端正常连接、错误服务端证书、明文 token | 正常路径通过，错误身份及明文凭据拒绝 |

当前这些验收尚未执行；此前真实 hbbs 签发、双 IP hbbr 逐端核销及重放拒绝证据继续有效，但不是同 IP 兼容证据。
