## 兼容范围

- 保持既有 ID、中继、API 端口及服务端签名公钥，登录、审批、禁用及逐端中继核销不降级；保留 1.4.9 下载入口与协议回归。
- 官方 1.5.0 的 `kx_version_for(0)` 选择原版加密。当前服务端不声明新版参数，继续使用签名 X25519 公钥、封装会话密钥和认证加密；探针明确拒绝把 v1 或要求签名参数的握手当作 v0。没有清空 Key 或改用明文。
- TCP/WSS 策略矩阵分别携带 1.4.9、1.5.0 版本字段，覆盖有效准入、五类策略拒绝与恢复、强制中继、逐端核销、重放拒绝。它是基于官方协议的探针，不是运行真实客户端。
- `/api/login-options` 维持 HTTP 200 和直接字符串数组；新增控制器回归以匹配 1.5.0 的严格解析。OIDC 新增 `apiDomain` 字段不作为回调地址的信任来源，现有服务端按请求入口生成认证地址。
- [官方说明](https://www.rustdesk.com/blog/rustdesk-1-5-0-webrtc-qos/)指出自托管客户端默认不启用 WebRTC。本轮不支持或下发 `enable-webrtc=Y`，不开放 TURN/ICE 旁路，不宣告 Kx v1。共享出口 IP 中继仍按既有安全策略拒绝。
- 新增 `/api/switch-grant` 的设备签名换向授权不在本轮实现，未提供此接口；已有常规连接不依赖它。浏览器完整远控仍需合法 Web 发行包，不因桌面客户端升级而关闭待办。
